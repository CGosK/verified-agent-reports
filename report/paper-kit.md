# Paper kit (Nov 15)

Everything needed to write the paper on the template. The rules below come from the Sprint page and its Google Docs template, read Nov 15 at 19:45 UTC. The numbers come from `report/tables.md` and `work/results/`.

## The template's rules

- **Template:** a Google Doc to copy (the Guidelines tab's "Submission Template" link). Submit a PDF of up to 25 MB through the form. Don't email it.
- **Length:** at most 8 pages, **not counting references and appendices.** So the tables beyond the two or three the argument needs can move to Appendix B without costing body pages. The outline's warning that "8 is tight" assumed they all sat in the body.
- **Required:** the title; an abstract of 150–250 words; authors and affiliations; and an appendix titled "Limitations and Dual-Use / Ethical Considerations".
- **Recommended sections:** Introduction, Related Work, Methodology, Results, Discussion, Limitations and Dual-Use, and References. Outline v5 already follows this order. The template itself recommends 4 pages, not counting references and appendix (Intro and Related Work 1 page, Methods and Results 2.5, Discussion 0.5); 8 is the cap.
- **LLM use:** no statement is required ("use AI tools however they help you"). The team answers for everything in the report, and made-up results or references disqualify it. The outline's one-line statement is enough.
- **Preexisting code:** must be marked in the README and the report. Nothing predates the sprint. The repository's first commit is `fe63989`, Nov 14, 2026 04:22 UTC (Nov 13 local time), and the README's "What predates the sprint" section says so.
- **Judging:** each criterion is scored 1–5: Impact Potential & Innovation, Execution Quality, and Presentation & Clarity. A judge may decline to score a report that's too unclear to follow.
- **Resubmitting:** use the same title, before the deadline (Nov 16, 11:59 UTC).
- **Optional:** a public repository, a 3–5 minute demo video (`docs/demo-script.md`; every command checked Nov 15 against the current code), slides, and a project image.

## Appendix A: facts added since outline v5's list

Each fact is followed by its source. Outline v5's own Appendix A bullet still stands.

1. **Anthropic's session count can be switched off by the team.** With `DISABLE_TELEMETRY` or `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` set, Anthropic counted 0 of 8 sessions, against 3 of 3 with neither set. The bill showed all of their tokens. vawr calls such a day "uncounted": the report is CONSISTENT, never VERIFIED, and setup warns about it. Source: Table 8; `work/results/telemetry_off_*.json`.
2. **VERIFIED needs whole UTC days when Anthropic counted more.** On a day the log starts, or the window ends, partway through, Anthropic's whole-day count may include sessions outside the log. If it counted more sessions than the log has, the day can't be confirmed and the report is CONSISTENT; if the counts match, the day passes. The bill check still covers the window minute by minute. Source: README, the paragraph that begins "VERIFIED needs the payer's Admin key".
3. **One known false alarm, documented rather than fixed.** With `DISABLE_TELEMETRY` set in the Claude desktop app's environment, one ~1,174-input-token request never reaches vawr's log. The bill check flags 174 tokens of it, so an honest team in that setup gets FAILED. Widening the background allowance would help teams that hide usage, so the setup warning tells people to unset the variable instead. Source: Table 8b; `work/results/telemetry_off_desktop_env.json`.
4. **Sessions that cross midnight UTC are untested.** No session in our logs runs across 00:00 UTC, so we don't know how Anthropic's daily count splits one. A minor limitation.
5. **The background allowance is 9,510 tokens per session** (input 1,000, output 1,500, cache read 7,010). There is one allowance per logged API-key session in the report's projects that has usage of its own, and a day fails if the allowance credited exceeds what Anthropic's own session count for that day justifies (its count, or the log's if smaller, times 9,510). Publishing it shows where hidden small-model usage could pass, which is dual use; the outline already says so. Source: `vawr/auditor.py`, `BACKGROUND_ENVELOPE`.
6. **Scope:** one operator, one machine, one Console organization. The runs used an API key and a Claude subscription, but the bill and sessions checks cover API-key usage only. Claude Code versions 2.1.322 and 2.1.325 (the latter A/B only). The weaker-work test covers planted weak work only (Table 7).
